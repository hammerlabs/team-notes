How to test the edit lock and long poll

Single user: log in, create or select a team, create or open a note, then Edit, Save and Done. The lock is renewed every renew_after_seconds while editing; the request log shows each call. Each renewal says whether you typed since the last one (active). After 10 minutes without typing or saving, the next renewal is refused (lock_idle) and the lock released; your text stays in the editor.

Two users on one screen (tick Two-user demo after logging in):

  1. Log in as an admin of a team (user A) and open a note. Tick Two-user demo and log in user B in the right pane. If B is not yet a member, press Add to the main user's team. B opens the same note and starts long-polling.
  2. Press Edit in A. B's poll wakes and B shows "Locked by A". Press Edit in B: 409 note_locked in B's pane.
  3. Change the text in A and Save. B's poll wakes and B shows the new text and version.
  4. Press Done in A. B shows Unlocked.
  5. Press Edit in B and type something. In A (an admin) press Break lock. B's poll (or its next renewal, lock_required) moves B to "lock lost"; B's text is kept.
  6. In A: Edit, change the text, Save, Done. In B press Edit (re-takes the lock, keeps B's text) and Save: 412 precondition_failed.

Each pane shows its long poll: waiting (with the elapsed time), woke after N ms, or 204 and polled again. Lower wait to see 204s sooner. Without the demo, a second window or tab (not a duplicated one, which copies session storage) works as user B too.
